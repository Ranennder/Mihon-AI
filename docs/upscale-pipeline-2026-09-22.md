# v0.1.27: ранний запуск апскейлинга главы

Пользователь заметил, что апскейлинг начинается после загрузки всех страниц, и предложил совместить скачивание с обработкой. Аудит подтвердил два барьера в режимах всей главы:

- При прямом скачивании `_download_and_run_direct_chapter_job` загружал все оригиналы последовательно и только после последнего вызывал GPU-обработку.
- При передаче с телефона `runWholeChapterRemotePrefetch` ожидал готовности всех страниц, создавал полный ZIP и только затем отправлял задание. Режим потока менял получение результатов, но сохранял этот барьер на входе.

Режимы отдельных страниц не ожидали всю главу. Количество одновременно работающих GPU-процессов для нового поведения увеличивать не требуется.

## Изменения

Прямое скачивание теперь использует загрузчик и обработчик с ограниченной очередью путей к подготовленным файлам. Первая страница обрабатывается отдельно, следующие уже готовые страницы объединяются в небольшие партии без ожидания загрузки всей главы. GPU-процессы используют прежний общий семафор. Готовые результаты доступны телефону до завершения скачивания остальных страниц; прогресс относится к конкретной странице. Ошибка поздней загрузки не должна скрывать уже полученные результаты.

Телефон передаёт первую незакэшированную страницу отдельно, затем партии до четырёх страниц. Загрузка оригиналов через существующий загрузчик продолжается во время обработки отправленной партии. Исходные индексы страниц, метаданные полной главы, проверка поколения кэша и fallback прямого скачивания сохраняются. Отмена останавливает отправку последующих партий.

Манифест URL для прямого задания по-прежнему готовится на телефоне до отправки задания. Изменение устраняет ожидание скачивания всех **изображений**; разрешение URL источником не превращается в работу компаньона. Время работы модели на реальной видеокарте этим изменением не измерялось. Для обоих улучшений нужны Android-приложение и компаньон v0.1.27.

## Проверка

Проверки должны доказывать перекрытие этапов: искусственно остановить загрузку следующей страницы и получить готовый результат первой до снятия блокировки. Отдельно проверяются отмена, ограничение очереди, сохранение индексов и частичных результатов при ошибке. Локальные проверки выполняются в ограниченных cgroup; релизные сборки и проверки Windows EXE — в GitHub Actions.
