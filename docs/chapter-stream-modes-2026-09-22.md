# v0.1.28: два варианта Chapter Stream

После v0.1.27 пользователь сообщил о замедлении и уточнил, что речь идёт о Chapter Stream. Проверка показала: отправка с телефона по-прежнему ожидала результата всей партии, прежде чем готовить и отправлять следующую. Прямое скачивание компаньоном уже работало одновременно с GPU, но маленькие партии чаще запускали модель заново. Публикация результатов direct batch также ожидала завершения всей партии.

## Поведение

В настройках AI для Chapter Stream появились варианты «Обычный» и «Параллельный». Обычный выбран по умолчанию, включая обновление с предыдущих версий: телефон отправляет один полный архив, а прямой загрузчик компаньона сначала скачивает всю главу и запускает один основной GPU процесс. Готовые страницы по-прежнему возвращаются потоком.

Параллельная передача с телефона использует две независимые корутины: подготовка/отправка и получение результатов. Семафор ограничивает незавершённую работу двумя заданиями; первая страница отправляется отдельно, следующие готовые страницы объединяются в партии до 16 без ожидания заполнения партии. Существующий загрузчик оригиналов продолжает работу независимо. При отмене новые партии не отправляются, защита поколения кеша исключает запись старого результата поверх ручного повтора.

Прямой параллельный загрузчик имеет отдельный поток скачивания, ограниченную очередь из 16 путей и один GPU процесс. Он обрабатывает первую страницу сразу, затем берёт до 16 готовых страниц без ожидания заполнения. Готовые изображения проходят проверку перед атомарной публикацией в каталог результатов во время работы GPU. Входные и промежуточные файлы не удаляются, пока рабочие потоки ещё используют их.

Переключатель относится только к Chapter Stream. Обычный Chapter при передаче с телефона сохраняет прежние партии 1+4. Для прямых заданий приложение передаёт `X-Reader-AI-Chapter-Mode: classic|parallel`; без заголовка новый компаньон выбирает classic. Неизвестный режим отклоняется до регистрации задания/изменения scope. `health` сообщает поддерживаемые режимы. Другие режимы нового клиента явно используют parallel для прямого скачивания. Для полного поведения нужны обе части v0.1.28.

## Проверка и ограничения

Проверки намеренно блокируют первую обработку и требуют, чтобы следующая загрузка или отправка завершилась до её разблокировки. Отдельные проверки охватывают обычный режим, лимит заданий, сохранение индексов, отмену, отказ direct с переходом на загрузку телефоном и раннюю выдачу страницы внутри ещё работающей партии.

Локальные Android проверки выполняются только через `scripts/gradle-local.sh`, Python — в отдельном ограниченном cgroup; релизные сборки и Windows EXE проверяются в GitHub Actions. Реальный GPU пользователя не доступен, сравнение времени обработки главы на его видеокарте не проводилось. Модель по-прежнему загружается на каждый GPU запуск, поэтому больший размер готовой партии уменьшает число запусков, но не гарантирует ускорение каждого источника. Блокирующее HTTP чтение может завершаться по сетевому таймауту после отмены; проверки перед последующими действиями предотвращают новые задания и запись отменённых результатов.

Локальный полный набор Python: 51 тест, 48 успешных, 3 Windows проверки пропущены на Linux.
